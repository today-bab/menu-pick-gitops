# Git 작업 규칙

사람이 하는 작업은 **이슈 → 브랜치 → PR → merge 커밋** 순서로 `main`에 붙인다. `main`에 직접 push하지 않는다.
frontend·backend 저장소와 같은 흐름이다.

> **예외**: backend CI가 이미지 태그를 바꾸는 `deploy: menu-pick-backend <커밋>` 커밋은
> deploy key로 `main`에 바로 push한다. 이 커밋은 사람이 만들지 않는다.

## 1. 이슈 만들기

- 작업을 시작하기 전에 GitHub 이슈를 먼저 만든다. 기능·장애 템플릿 중 하나를 골라 채운다.
- 제목 형식: `[<제목 타입>] <한국어 요약>` (예: `[Feat] Grafana에 캐시 패널 추가`). 제목 타입은 아래 표를 따른다.
- 이슈 하나는 브랜치 하나, PR 하나로 끝낼 수 있는 크기로 잡는다. 크면 이슈를 나눈다.

## 2. 브랜치 만들기

`main` 최신 상태에서 이슈 번호를 넣어 브랜치를 만든다.

```sh
git switch main
git pull
git switch -c feat/5-valkey-panel
```

형식: `<타입>/<이슈번호>-<짧은-설명>` (영어 소문자, 단어는 `-`로 연결)

| 타입    | 이슈·PR 제목 타입 | 용도                         |
| ------- | ----------------- | ---------------------------- |
| `feat`  | `[Feat]`          | 배포 구성·모니터링 추가·변경 |
| `fix`   | `[Fix]`           | 장애·오동작 수정             |
| `docs`  | `[Docs]`          | README·주석 등 문서          |
| `chore` | `[Chore]`         | 템플릿, 설정 등 기타         |
| `ci`    | `[CI]`            | GitHub Actions 워크플로      |

## 3. 커밋

형식: `<타입>: <한국어 요약>` — 타입은 브랜치 타입과 같은 목록을 쓴다.

```
feat: Grafana에 캐시 미스 처리 방법 패널 추가
fix: 배포 중 502를 막도록 백엔드 종료 전 preStop 대기 추가
```

- 커밋 하나는 하나의 책임만 담는다. 한 브랜치에 작은 커밋 여러 개가 쌓여도 괜찮다.
- 요약은 무엇을 왜 바꿨는지 드러나게 쓰고, 마침표를 붙이지 않는다.
- 비밀값은 평문으로 커밋하지 않는다. Sealed Secrets로 암호화한 `SealedSecret`만 커밋한다.

## 4. PR 열기

- 제목은 이슈 제목과 같은 `[<제목 타입>] <한국어 요약>` 형식으로 쓴다.
  커밋 메시지는 `<타입>: <요약>` 그대로 둔다.
- 본문은 PR 템플릿을 채운다. `Closes #<이슈번호>`를 넣어 머지 시 이슈가 자동으로 닫히게 한다.
- 규칙 검사(Conventions: 브랜치 이름, PR 제목, `Closes #N`)가 통과해야 머지한다.

## 5. 머지

- **Create a merge commit**으로 머지한다. squash·rebase 머지는 쓰지 않는다.
  머지하면 Argo CD가 곧바로 클러스터에 반영하므로, 기능 단위로 되돌릴 때 `git revert -m 1 <merge 커밋>`을 쓴다.
- 머지 후 브랜치는 삭제한다.
